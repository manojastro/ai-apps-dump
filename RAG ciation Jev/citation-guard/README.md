# Citation Guard

Stage 1 of the Jev decision layer. Citation Guard runs after an LLM writes a cited answer and
before the answer reaches the user. It checks every claim against the source it cites:

1. **Check A, deterministic quote match (no model).** Is the quoted text really in the source?
   If not, the claim fails as a fabricated quote and no model is called.
2. **Check B, Jev judgment.** If the quote exists, Jev answers one Choice question: does the
   passage `supports`, `contradicts` or `says_nothing` about the claim?
3. **Gate (code, not the model).** Thresholds in `config.yaml` turn probabilities into
   `PASS`, `FAIL_FABRICATED_QUOTE`, `FAIL_CONTRADICTED` or `HUMAN_REVIEW`; the answer is
   `DELIVER`, `BLOCK` or `REVIEW`.

**Latest results:** [reports/LATEST.md](reports/LATEST.md) (generated by `citation-guard report`;
numbers are never copied here by hand). Check each row's MODE: only `LIVE` rows come from
real model calls.

## Setup (Windows PowerShell)

Needs [uv](https://docs.astral.sh/uv/). uv fetches Python 3.12 if needed.

```powershell
cd citation-guard
uv sync
Copy-Item .env.example .env   # then fill in keys
uv run pytest                  # all offline
```

Keys (in `.env`, never committed):

| Variable | Used by | Without it |
|---|---|---|
| `TYPESAFE_API_KEY` | Jev judge, `models` | Jev runs are blocked; MOCK still works |
| `OPENROUTER_API_KEY` (or the variable named in `llm_provider.api_key_env`) | generator, LLM baseline | `generate` and `--judge llm` are blocked |

To use Azure OpenAI instead of OpenRouter, change `llm_provider.base_url` to
`https://<resource>.openai.azure.com/openai/v1/`, `api_key_env` to `AZURE_OPENAI_API_KEY`,
and the model names to your deployment names.

## Commands

| Command | What it does |
|---|---|
| `uv run citation-guard ingest` | Download (if missing), clean and section every document in `data/sources/manifest.yaml` |
| `uv run citation-guard models` | List Jev models via the SDK (needs key); shows the pinned version |
| `uv run citation-guard generate` | Run the generator LLM (system under test) on `data/eval/questions.yaml` |
| `uv run citation-guard build-claims` | Merge generated + planted claims into `data/eval/claims.jsonl`, keeping reviewed labels and existing splits |
| `uv run citation-guard label` | Interactive review: confirm or change each label (`--all` to revisit reviewed ones) |
| `uv run citation-guard verify examples/answer_example.json --judge mock` | Verify one answer file |
| `uv run citation-guard eval --judge mock` | Run a judge (`jev`, `llm`, `mock`, `stringmatch`) over all claims; writes `runs/<run_id>/` |
| `uv run citation-guard report` | Per-run reports + comparison summary in `reports/` (latest run per judge, or `--run <id>`) |
| `uv run citation-guard serve` | Local API on http://127.0.0.1:8000 (`POST /v1/verify`, `GET /health`) |

## Running LIVE

```powershell
uv run citation-guard models
uv run citation-guard generate
uv run citation-guard build-claims
uv run citation-guard label
uv run citation-guard eval --judge jev
uv run citation-guard eval --judge llm
uv run citation-guard eval --judge stringmatch
uv run citation-guard report
uv run pytest --live
```

- `models` confirms your account can reach Jev. The pinned model (`jev.model` in `config.yaml`)
  is a concrete version, never `jev-latest`.
- Every run stops before its first call if it would need more than `run.max_api_calls_per_run`
  (default 500) external calls.
- A bad key or missing access stops the run. It is never written out as "all claims to review".
- Thresholds are tuned on the **dev** split only; results are reported on the **test** split.
  The LLM baseline gets its own tuning, because its probabilities are prompted estimates, not
  calibrated ones.

## Layout

```
citation_guard/   ingest, quote_match, judges/{base,jev,llm,mock}, gate, generate,
                  pipeline, evaluate, labeling, report, api, cli, config
data/sources/     raw documents + manifest.yaml (download date, sha256)
data/processed/   cleaned text + sections + offset map
data/eval/        questions.yaml, planted_claims.yaml, claims.jsonl
runs/<run_id>/    decisions.jsonl (one line per claim) + run.json
reports/          eval_<date>_<run_id>.md/.csv, summary_<date>.md, LATEST.md
docs/             DESIGN.md, LIMITS.md
```

See [docs/DESIGN.md](docs/DESIGN.md) for architecture and threshold policy, and
[docs/LIMITS.md](docs/LIMITS.md) for what this does not do.
