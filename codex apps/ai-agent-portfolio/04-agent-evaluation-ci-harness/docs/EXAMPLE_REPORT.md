# Example report interpretation

A good deterministic demo run should have full task success, groundedness, citations, tool selection, and unanswerable handling, about 35 ms modeled p95 latency, no unsafe tool calls, and cost below the sample gate.

A `--mode bad` run intentionally returns unsupported advice, wrong citations, a forbidden tool, 900 ms latency, and excessive cost. The comparison lists every task-success change. The gate should fail absolute, relative, latency, cost, and safety checks. Actual results are generated by `evalharness report`; this document intentionally avoids fabricated benchmark claims.
